# Changelog

All notable changes to NeelKIT. Dates are the day the work landed, not a
release schedule.

## [Unreleased]

### Changed — 2026-10-02

- Go module path is now `github.com/neeldas0032/NeelKIT-AI-voice-assistant`,
  matching the published repository, so `go install` and imports resolve.
- `docs/architecture.md` AD-002 rewritten: the running normaliser was replaced
  by whole-slice normalisation, and the doc now says why.
- README rewritten for publication, with a system diagram
  (`docs/system-diagram.svg`, generated by `scripts/gen_diagram.py`) and a
  sequence diagram of one voice command.

### Fixed — 2026-10-01

- **The page went blank after saying "hello".** A turn that runs no tool was
  sent with `"calls": null`; the telemetry panel called `.reduce` on it while
  rendering and React unmounted the whole app. Turns and intents now always
  serialise `calls` as a list, the client also tolerates a missing list, and a
  page-level error boundary keeps any future rendering bug from blanking the
  app. Reproduced in Chromium with a fake microphone; regression test
  `TestTurnWithNoCallsSerialisesEmptyLists`.
- **The API key changed on every restart.** It was generated at startup and
  held only in memory, so the key saved in the browser stopped working (401)
  each time the server restarted. Its salted hash is now stored in the existing
  `api_keys` table; the key printed on first run keeps working, and
  `-rotate-key` issues a new one. Test: `TestAPIKeySurvivesRestart`.

### Fixed — 2026-09-28

Found by running on a CPU laptop rather than the test machine. Every one of
these was invisible with the synthetic model, which decodes in milliseconds.

- **Voice stalled for tens of seconds on CPU.** Preview decodes ran inline in
  the audio path. Once one took longer than the preview cadence (easy on a
  CPU), every 32 ms VAD window started another full decode, so three seconds of
  speech took over ten seconds just to ingest, and the endpoint arrived late.
  Previews now run on their own goroutine, one at a time, and back off to twice
  their own cost so the final decode is not starved. Reproduced and guarded by
  `TestSlowPartialsDoNotStallAudioIntake`.
- **Push-to-talk never produced an answer.** The web client never told the
  server the button was released. Stopping the microphone now commits the
  utterance, which also stops words said just before the click being lost.
- **The utterance after a stop or cancel was sliced from the wrong audio.** The
  endpointer's window count restarted but the ring buffer's did not, so the
  recogniser was handed silence or old speech. Utterances are now anchored to
  the ring (`TestUtteranceAfterCancelIsSlicedFromTheRightAudio`, which fails
  with 0% speech without the fix). Push-to-talk utterances no longer include
  the previous one.
- **Features were normalised against silence.** Live audio used a decaying
  running normaliser whose statistics were dominated by the trailing hangover
  silence. Every request is a complete slice, so all decodes now use
  whole-slice per-feature normalisation, as the model was trained.
- **First and last sounds clipped.** Utterances now keep ~320 ms of audio before
  Silero became confident and ~190 ms after, never reaching into the previous
  utterance.
- **Slow language model reported as unreachable.** A client-level HTTP timeout
  turned "too slow" into a transport error. Deadlines now come from the context
  and produce a reply that says the model was too slow.

### Added — 2026-09-28

- Ollama requests pin a 4096-token context (the tool list alone is ~1,100
  tokens; older Ollama defaults silently dropped the system prompt) and keep the
  model loaded for 30 minutes.
- The model is warmed at startup, so the fixed prompt prefix is already cached
  when the first question arrives.
- `nkbench asr` reports word error rate from `transcripts.tsv` or `.txt`
  references, and prints what the recogniser heard for every clip.

### Added — 2026-09-14

Phase 2 through 11 in one pass: a working end-to-end system.

**Speech**
- ONNX Runtime engine for Parakeet TDT 0.6B with a tensor-reusing decoder pool,
  warm-up at startup, and graceful shutdown that waits for in-flight decodes.
- Word-level timestamps at 80 ms resolution and per-token softmax confidence,
  both derived from data the decoder already produces.
- Mel extractor with precomputed FFT twiddle factors and zero allocations in
  the per-frame path.
- Anti-aliased resampling (windowed-sinc low pass before decimation).
- Long-audio windowing with energy-based boundary placement and seam dedup.
- Priority admission: live previews are shed before completed utterances.

**Realtime**
- WebSocket session with VAD endpointing, streaming partial transcripts and a
  final decode on endpoint.
- Silero VAD integration plus a pure endpointing state machine with hysteresis.
- Single-writer socket with bounded outbound queue; previews drop under lag,
  finals and approval prompts never do.

**Assistant**
- Transcript normaliser: developer lexicon, identifier repair, spoken numbers.
- Two-tier intent router: compiled grammar first, language model second.
- Pluggable LLM provider with an Ollama implementation and a fake for tests.

**Tools**
- Self-registering tool registry with JSON Schema descriptors and risk levels.
- Pure policy gate whose decisions can only ever be escalated, never relaxed.
- Sandbox built on `os.Root`, argv-only execution, binary allowlist,
  destructive-argument denylist, constructed child environment.
- Thirteen built-in tools across fs, git, search, notes and shell tasks.

**Platform**
- SQLite storage with embedded migrations and FTS5 transcript search.
- Hashed API keys with constant-time verification and WebSocket ticket exchange.
- Dependency-free Prometheus metrics, structured logs with request correlation.
- Next.js interface: live session, history, tool registry, settings.
- `nk` command-line client that speaks only the public API.
- Docker images and a compose stack.

### Added

- `cmd/nkbench` — a benchmark harness measuring real-time factor and per-clip
  latency over a WAV corpus, grammar routing latency, and normalisation
  throughput. It ships no numbers of its own: `docs/performance.md` states the
  method and leaves the results tables empty until someone runs them on real
  hardware.
- `docs/openapi.yaml`, checked against the router by
  `TestOpenAPIMatchesTheRouter`. A registered route missing from the spec, or a
  documented operation no route serves, fails the build in either direction.
  `Server.Routes()` records patterns at registration because `http.ServeMux`
  does not expose what it holds.
- Playwright end-to-end tests (`web/e2e/`) driving a real browser against a real
  server and a real sandbox: a read runs unprompted, a write writes nothing until
  approved, denial leaves the disk untouched, and an approved path traversal is
  still refused. Wired into CI against the synthetic model, so the job needs no
  model download.
- `scripts/demo.sh` and `scripts/demo-sandbox.sh` — deterministic scripted runs
  for recording, the second demonstrating that approving a traversal does not get
  it past the sandbox.
- `make measure` and `make e2e`.

### Changed

- The interface was rebuilt on the **Developer Voice Workstation** design system
  (`docs/design-system.md`): obsidian canvas, frosted glass panels with a 1px
  specular bevel, recessed terminal surfaces, and a signature gradient reserved
  for the live audio path. Geist and JetBrains Mono, self-hosted; the icon font
  was replaced with inlined SVG so no page load reaches a CDN.
- Layout is now tri-panel above 1280px — anchor rail, execution canvas, telemetry
  rail — filling the viewport, with the transcript scrolling inside its own panel
  so the microphone control is never scrolled away mid-sentence.
- `RealtimeSession` gained `onSpectrum`, exposing 32 real frequency bands off the
  existing `AnalyserNode`. The waveform shows captured audio rather than an
  animation, so it is flat when the microphone is closed.
- Final transcripts now render per-word confidence: any word the recogniser
  scored below 0.85 carries a dotted underline. The data was already on the wire
  in `transcript.final.words[]` and had no surface.
- The telemetry rail reports measured figures only — segmented turn latency,
  real-time factor, transcript confidence, grammar-versus-model routing split,
  device and worker count, and executed calls. Panels from the reference design
  with no corresponding measurement (tokens/sec, TTFT, VRAM, context-window
  occupancy, AST diffs) were left out rather than filled with plausible numbers.

### Fixed

These were found by running the system, not by reading it.

- Engine warm-up ran before the engine marked itself ready, so it failed on
  every start with "engine closed" and silently gave up the benefit it exists
  for.
- HTTP metrics labelled every request `route="unmatched"`: `r.Pattern` is set on
  the request `ServeMux` passes *into* a handler, not on the one an outer
  middleware holds.
- The approval reply lower-cased the command preview and cut it at the first
  period, turning `NOTES.md` into `notes` — a quiet distortion of the one
  string the user is asked to approve.
- Spoken file paths were run through identifier normalisation, which collapsed
  `../../etc/passwd` into `etc/passwd`. Contained by accident, but the user was
  told the file did not exist rather than that they had asked to leave the
  project.
- The audio ring buffer did not advance its absolute counter for samples
  dropped in an oversized write, so every index handed out afterwards pointed
  at the wrong audio.
- `asr.Priority`'s zero value was "never queue, shed aggressively"; a caller
  that forgot to set it had its request silently dropped under load. The zero
  value is now the conservative one.
- API key verification used PBKDF2 at 100k iterations, adding 20 ms to every
  authenticated request for no security benefit on a 256-bit random secret.
- `decoderWorker.destroy` boxed typed-nil tensors into non-nil interfaces.
- Grammar patterns with leading optional groups could never match.
- `fs.list` said "1 entries in src". The summary is read aloud, where number
  agreement is the difference between a sentence and a template.
- The nav clipped "SETTINGS" at 390 px. The link padding now tightens below
  420 px instead of the labels shrinking everywhere else.
- `--text-faint`, used for every silkscreened label at 9.5 px, sat at roughly
  3.2:1 against the panel in both themes. Both faint and dim tones were raised
  to clear 4.5:1.

### Notes

- Transcript search uses prefix indexes rather than the Porter stemmer: Porter
  stems "deployment" to "deploy" but the query "deploy" to "deploi", so
  searching for the word you just said found nothing.
- Prometheus's official client pulls in six modules for fifteen instruments, so
  the exposition format is implemented directly instead. Swapping the library
  back in is contained behind `internal/observability/metrics`.
